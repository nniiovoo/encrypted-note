# Native credential custody

Status: ready-for-human — implementation present in this source tree; physical acceptance pending. Refs [#13](https://github.com/nniiovoo/encrypted-note/issues/13). Master Password and Recovery Key entry, new-password suggestion/strength/confirmation, Recovery Kit display/confirmation and stored Wallet readouts now use Rust-owned native controls. They are not WebView IPC values. Windows and Mac physical keyboard, accessibility and capture acceptance remain open.

## Native boundary

The WebView requests a named operation with non-credential arguments. Rust validates the current action, target Note, field and Kind, freezes its arguments and encrypted source state, and owns the native controls plus their callback. The [coordinator](../src-tauri/src/native_coordinator.rs) serializes native operations; [core jobs](../src-tauri/src/core/native.rs) derive credentials off the core mutex and commit only after rechecking the captured operation, phase, epoch, session generation, document counter, exact file bytes, deadline and Sharing Guard.

[AppKit controls](../src-tauri/src/native_credential/mac.rs) replace the existing capture-protected main window's content view while retaining the hidden WebView. The [Windows adapter](../src-tauri/src/native_credential/windows.rs) uses native single-line password EDIT controls in the same protected main window. Input, Recovery Kits and Wallet readouts do not use a separate browser window. Native controls clear their text when they close and return wiping Rust buffers; that cannot promise physical erasure of OS string/editor copies. Apple documents [secure text fields](https://developer.apple.com/documentation/appkit/nssecuretextfield) and Microsoft documents [ES_PASSWORD](https://learn.microsoft.com/en-us/windows/win32/controls/edit-control-styles).

Only the native callback can submit credential text to the frozen action. A request ID can cancel a request; it cannot authorize a different action. No credential string, generic authentication boolean, reusable approval grant or retained Wallet Key is returned to the WebView. Ordinary Hidden Field Show still returns its single authorized value under the existing reveal rules. Stored Wallet values use a native readout and return only completion through IPC; show-and-copy writes the clipboard in Rust.

## Implemented callers

| Operation | Native behavior | WebView result |
|---|---|---|
| Create Vault | Choose/confirm a strong Master Password, derive keys, show the Recovery Kit and confirm its final groups natively. No Vault file is saved before confirmation. | Completion/status |
| Unlock | Select Master Password or Recovery Key; parse/normalize and apply persistent credential delays in Rust. | Completion/status |
| Set new password after Recovery Key | Choose/confirm the replacement password natively; persist the candidate before leaving recovery state. | Completion/status |
| Wallet Show, accessible Show and Show-and-copy | Authenticate the exact Note/field, hold a transient Wallet Key, then show the value in native controls. Hold/timed rules, bounded extension and the shared disclosure allowance remain enforced. | Completion only |
| Whole-field copy | Rust decides whether the Note is a Wallet Kind; prompt natively when required and copy in Rust. | Completion only |
| Wallet create/edit/trash/delete/Empty Trash | Freeze the input and target set, request the fresh Master Password, derive the Wallet Key only for that action, recheck state, and wipe it afterward. | Existing non-secret action result |
| Backup or Safety Copy inspection | Collect the selected copy's credential natively and bind the exact source. Preserve preview expiry and explicit installation. | Preview metadata only |
| Password change or Key Rotation | Collect current/new password and confirmation. Rotation's new Recovery Kit stays native until confirmed; failed/cancelled candidates do not replace the committed Vault. | Completion/status |
| Loosen Auto-lock | Normalize the complete candidate, collect native Master Password only for a weaker rule, and persist before applying it. Tightening stays prompt-free. | Non-secret settings |
| Enable Quick Unlock | Fresh native Master Password proof of the current committed Vault precedes local Secure Enclave enrollment. | Availability/status only |

Raw password-generation/scoring IPC, password arguments, React password modals and Recovery Kit state have been removed from the app callers and registered command/capability routes. New-password controls call the existing policy internally. Native create calibration is owned by the operation lease. The terminal Emergency Reader retains its separate no-echo credential entry; it has no biometric route and is not an agent integration, though any program in the owner's account can run it.

## Cancellation, retention and limits

Native operations expire after two minutes, with these exceptions: choosing a new Master Password has up to ten minutes and ends after five minutes with no typing or clicks; typing a Recovery Key has five minutes; the Recovery Kit step has its own ten minutes; a Wallet readout has its own two minutes from when the Master Password is accepted, and its reveal limits can end it sooner. Auto-lock and every other invalidation listed here can end any panel sooner. After a valid submit on a long entry, the core and coordinator allow two more minutes for key derivation and the commit; every commit recheck stays. Escape/close, explicit cancellation/navigation/reload, owner Lock, timeout, sleep, screen lock, user switch, focus loss, replacement/password/rotation transitions, target mutation/removal or Sharing Guard arrival invalidates pending work. Rust rejects stale callbacks before failed-password accounting or any plaintext, clipboard or disk effect. A cancelled derivation cannot revive a held reveal or approve another action.

On the Recovery Kit step the first Escape or Cancel only asks, and a second press within ten seconds cancels. Until then the key stays on screen; switching apps, Lock, the Sharing Guard and the time limit still close it at once. While the step shows Please wait…, Escape and Cancel are rejected like every other action; switching apps and the time limit still close it. On that step, and on Recovery Key entry and the new-password boxes, one brief Retry within 350 ms of a successful check paints nothing and still rejects actions, so a press in that moment does nothing and says nothing. A suggested password, and on Mac an opt-in view, can stay on screen that much longer, because the Sharing Guard can't update while the core is locked either. Typing in a box still lands while the core is busy, on every panel with a box: a missing key in a box of dots can't be seen, and it would change the password. On Mac the field editor takes the key before anything checks it. On Windows the box's subclass lets plain typing through, except in a blanked Recovery Kit retype box, and rejects arrows, Delete, Tab and Ctrl+V until the core is free.

Master Password and Recovery Key entry boxes stay secure, masked fields. The Recovery Kit step's retype box shows what is typed, since the key is on screen right above it, so nothing may carry its text away: on Mac its own field editor refuses copy, cut, dragging out, Services, the right-click menu, Writing Tools and Look Up, which would open a system window that Capture Hiding doesn't cover, and on Windows the box refuses copy, cut and the context menu. Typing, Select All and paste by keyboard or the Edit menu stay; right-click Paste goes with the menu. Two opt-in views exist on Mac only, each off by default. **Show what I type**, on Recovery Key entry, is off each time and is never remembered; it shows a separate read-only line that holds only symbols a Recovery Key can contain, grouped and capped at 28 characters, with anything else as `?`. Letters and digits of a password typed there by mistake would still show. It turns off after about a minute with no real key press. The typed key stays in the box until the panel closes, so someone at the keyboard can tick it again or press Continue. **Hold to show what I typed**, on the New and Confirm Master Password boxes, shows a snapshot while held, for about ten seconds at most, under a caption with that box's label: the one of those two boxes that has the focus and holds text, otherwise the last-edited one, and never the Current box. A keyboard hold has no box in focus, so it shows the last-edited one. The button stays disabled until one of the two boxes has text. Both views are hidden from the accessibility tree, blank when the panel suspends or closes and don't come back on their own, and refuse while a known sharing app is detected, even after its Shield was dismissed; a plain line then says why and names no app. A brief busy core is not a detection: the timer leaves them as they are and the Retry grace above applies, but a press during it shows nothing. Capture Hiding is best effort, so text on screen can still be captured. A suggested password is a third case of plain text on screen, on both platforms: Suggest a password draws it on a separate line so it can be written down, assistive tools can read that line, and it is not refused while a known sharing app is detected after a dismissal. Assistive tools can also read the Recovery Kit step's key line and its retype box. Recovery Key entry also has a character count and a local typo check on both platforms; the check runs no key derivation and counts no attempt, and its messages hold only counts and group numbers. Physical runs with fake values are required on Mac before this is claimed to work.

New-password boxes are read at typing pauses for length, match and strength. Those checks leave extra unwiped copies inside zxcvbn and, on Mac, in NSString, within the best-effort limits below. Continue always re-runs the real checks. Keys pressed before a native box appears go to the WebView.

Native activity keeps the existing idle timer current. Wallet readouts are bound to the native operation epoch and current reveal identity, so an obsolete panel cannot hide or extend a newer field. Recovery Kit cancellation rolls back the uncommitted creation/rotation state. Plaintext values and transient Wallet Keys are dropped on every completion/error path; the app does not cache a previous Master Password approval for future Wallet actions.

Ordinary Note entry/checks, including newly entered Wallet Hidden Fields, remain in the WebView. Explicit ordinary Show values also enter JavaScript. A compromised renderer could read those inputs/outputs or draw a convincing fake credential prompt; native custody cannot prevent an owner typing into that imitation. The native panels remove the app's actual Master Password, Recovery Key, Recovery Kit and stored Wallet readout routes from renderer memory. They do not protect a compromised Rust/native process, keylogger, administrator or operating system. OS/native editor buffers and the stack remain best effort.

## Validation still required

Fake-data core/coordinator tests cover creation and Recovery Kit confirmation, both unlock kinds, recovery reset, Wallet mutations/readouts, both password-change modes, copy inspection, Auto-lock weakening/tightening and stale/expired/cancelled operations. `npm run typecheck` checks WebView calls against `src/api.ts`; `/fixture.html` only draws screens. The presence of these tests is not evidence of physical native behavior.

Sharing Guard regression: with a detected sharing app running, create a fictional Vault, acknowledge the guard, and lock. The shield must appear before either native unlock route; after an explicit acknowledgement, Master Password unlock must open native controls. Cancelling leaves the Vault locked; a new or restarted sharing app must invalidate the pending native action. Repeat after restarting the app with the fictional Vault already present. A sharing warning arriving while already locked must not move focus to its acknowledgement button.

Open Note regression, with a fictional Seed Phrase: from an open Note, Continue: hold to show, Copy and Move to Trash must keep their panel open, and switching apps must still close it. With a fictional Login: Show, then switch apps; the value must disappear and the reveal must end.

Recovery Kit retype box on Mac, with a fake key: type a fake value, then try Cmd+A then Cmd+C, Cmd+X, Edit > Copy, right-click, the app menu's Services and dragging the selection out. The clipboard must not change and nothing must leave the box, while typing, Cmd+V and Edit > Paste still work. Then try a force click, a three-finger tap and Ctrl-Cmd-D on the typed text, both with nothing selected and after Cmd+A: no Look Up window may open. The force-click route relies on private AppKit names, and the route Ctrl-Cmd-D takes hasn't been traced, so if it opens Look Up, that needs its own fix. Also with Pinyin selected: the box takes letters as typed, and normal input comes back after the panel closes. During a forced core-lock blink long enough to say Please wait…, the retype text and caret must be hidden, and must come back. Confirm the panel still opens on macOS 13 or 14 if a machine is available, and repeat the Look Up gestures there.

Other Mac checks, with fake values: with Keyboard navigation off, Tab reaches Show what I type, Suggest a password, Hold to show and Reset to 20 seconds, and Space works on each. Hold to show on New after typing both boxes, by mouse with Keyboard navigation off and on. With a known sharing app running after a dismissal, the two views go grey and the line explains why. A forced core-lock blink leaves Show what I type ticked and a hold showing, and typing survives it, also with Full Keyboard Access on. A three-finger tap on a Wallet readout opens no Look Up window.

Accessibility, Mac, with fake values: tick Show what I type, then press and hold the Hold to show what I typed button. While each line is shown, VoiceOver and Accessibility Inspector must not find the line or its text, either by walking the tree or by pointing at the line. A test (`src-tauri/tests/mac_typed_line.rs`) checks the line under its parent view, not a real panel on screen.

Keyboard focus, Mac, with fake values: Tab to Suggest a password and press Space, then press Space again: the words must not silently change, and the focus has left the button. Hold Space on that button too. After a suggestion is forgotten by typing in New or Confirm, the focus stays in that box. Tab to Hold to show what I typed and press Return with a weak password, then type: the letters are added to the end of New and don't replace it. Tab to Show what I type and press Return with a short Recovery Key, then type: the letters are added to the end of the box.

Settings, Mac: click the Vault folder path and press Cmd+C: only the path is copied. Run `tmutil isexcluded` on the helper folder and record the answer, because the guide says full-computer backups may copy the Agent Key file. Show in Finder, on the signed sandboxed build with a fictional Vault: if macOS asks whether Finder may access data from other apps, stop and review; do not tell the owner to allow it, because ADR-0001 relies on that container protection. The guide's advice to allow Terminal for the Emergency Reader is a separate case.

Both platforms: after a Recovery Key unlock, Choose a Master Password has the keyboard. A Return held from the panel must not press it, a later Return opens the box, and Escape in the box puts the keyboard back on the button.

Windows checks on a real PC, with fake values: Create and Unlock panels stay open. Alt-Tab with a panel open closes it, with no value left on screen. Alt-Tab with a Hidden Field shown hides it and ends the reveal. Alt-Tab with lock on app switch turned on locks. Enter on a focused Cancel cancels, except on the Recovery Kit step, where the first press only asks. Clicking Cancel once on that step, then typing, puts the keys in the box. Click Suggest a password, then press Enter: it asks if you wrote it down and the words don't change. A refusal after clicking Continue leaves the keys going to a box. Typing right after a panel opens and after dragging the window by its title bar must add one mask dot per key; if not, file a separate security issue (ADR-0003). With the core lock held on purpose (this needs a temporary debug build, because nothing in the app can force it), each key in a Master Password, Recovery Key, New or Confirm box must still add one mask dot. On the Recovery Kit retype box, the input method stays off, and a Retry long enough to say Please wait… masks the typed text and then unmasks it. Show in File Explorer opens the Vault folder. Fonts and scaling at 100%, 125%, 150% and 200%: record the System font's height, because the panel's rows use fixed pixels. Those checks belong in the Windows table in [capture-test.md](capture-test.md).

Touch ID, in addition to its own checklist: a closed lid and a disconnected Touch ID keyboard should each keep Touch ID on. That rests on Apple's documented error codes and hasn't been seen on hardware.

Run the current local app on real macOS and Windows for complete create/recovery/Wallet/copy/rotation/settings flows, the Agent Companion's Start dialog on Mac (Return and Escape cancel, and the Vault stays Unlocked while it's open), native keyboard behavior, VoiceOver/Narrator, held Space/button release, long/control-character readouts, lock/switch/sleep races and first-frame capture behavior. Inspect only sanitized outcomes and fake fixture markers when checking IPC/events/logs; real credential or Wallet contents must not enter reports. Existing capture results from an older UI do not validate the new native controls. Touch ID has its own [physical acceptance checklist](quick-unlock-design.md#boundaries-and-acceptance-still-pending).
