# Native credential entry: proposed migration

Status: ready-for-human — design only. Refs [#13](https://github.com/nniiovoo/encrypted-note/issues/13). The Master Password and Recovery Key still pass through the WebView today; no native prompt is implemented. This map includes the Auto-lock reauthentication implemented for [#30](https://github.com/nniiovoo/encrypted-note/issues/30) in [PR #51](https://github.com/nniiovoo/encrypted-note/pull/51); its password entry remains in the WebView.

## Native ownership and operation contract

Use native controls owned by Rust's platform adapter, inside the existing protected main window: AppKit secure fields on Mac and Win32 single-line password EDIT controls on Windows. Keep the WebView out of native text/delegate callbacks. Apple documents [secure text fields](https://developer.apple.com/documentation/appkit/text-field) and their [non-copying field editor](https://developer.apple.com/documentation/appkit/nssecuretextfieldcell); Microsoft documents [ES_PASSWORD](https://learn.microsoft.com/en-us/windows/win32/controls/edit-control-styles) as display masking. These are control primitives, not a promise of wipeable OS memory or protection against an administrator/compromised native process. Sources reviewed 2026-10-21.

The WebView requests a named operation with non-credential arguments. Rust derives the actual action, target Note, field and Kind from validated current state, freezes its arguments, and owns the credential panel plus the completion callback. Only that callback may submit native text to the existing password/recovery checks. Return the action result/status or the already-authorized single Hidden Field; never return credential text, a reusable approval token, a generic authentication boolean or a retained Wallet Key. A request ID may cancel one pending operation; it cannot authorize another.

New-password suggestion, strength feedback and confirmation belong inside the native panel too. Migrate Recovery Key entry and Recovery Kit display/confirmation in the same custody design: leaving a reusable Recovery Key in JavaScript preserves an alternate route into the Vault. This is an explicit extension of #13's Master Password requirement and needs review before implementation; a partial implementation must retain that caveat in ADR-0003. Ordinary Note Hidden Field entry/checks remain in the WebView under the existing model.

## Exact command and caller reach

|---|---|---|
| `suggest_passphrase`, `assess_password` | `components.tsx: NewPassword` | Remove credential-generating/scoring WebView routes; native new-password controls call `policy` internally, including two-entry match and existing strength rules. |
| `create_vault`, `confirm_recovery_kit` | `Start.tsx: NoVault → NewPassword → RecoveryKit`; `App.tsx: kit` state | Start creation without a password argument. Native chooses the Master Password, shows the generated Recovery Key once and collects confirmation; no `RecoveryKeyShown` value or `lastGroups` crosses IPC. Keep nothing-on-disk-before-confirmation. |
| `unlock` | `Start.tsx: Locked` | IPC selects only the credential kind; native collects Master Password or Recovery Key. Preserve parsing, NFC normalization and persistent wrong-credential delays. |
| `set_new_password` | `Start.tsx: NewPasswordScreen` | Native new-password panel in `needs_new_password`; no password argument. Keep recovery-reset save/rollback rules and Lock/Cancel behavior. |
| `show_wallet_field`, `show_and_copy_wallet_field` | `Note.tsx: WalletShow` | Native holds the password and action-specific hold/Space or 20-second controls. Bind exact Note/field/mode; preserve release-before-derivation cancellation, the three timed extensions and Seed Phrase copy warning. No cached password or Wallet Key between attempts. |
| Wallet `copy_field` | `Note.tsx: NoteView → PasswordModal` | Native password and exact field/copy confirmation; perform one core copy, with the existing 30-second Wallet clipboard limit and disclosure checks. |
| Wallet `create_note`, `update_note` | `Note.tsx: Editor.save/begin → PasswordModal` | Remove optional password arguments. Rust decides whether current Kind requires a prompt, freezes the full input, and native confirms the specific save (including Save and add another). All Wallet edits, even visible-only changes, still require the Master Password. |
| Wallet `trash_note`, `delete_forever`, `empty_trash` | `Note.tsx: NoteView`; `Home.tsx: Trash` via `PasswordModal` | Native confirms the exact Note/removal action. For Empty Trash, bind the actual target set and recheck Wallet membership before commit; do not trust the WebView's `holdsWallet` decision. Ordinary non-wallet paths keep existing rules. |
| `inspect_backup`, `inspect_safety_copy` | `Settings.tsx: ReplaceVault`, reached from NoVault, Locked and Settings | Native collects the selected copy's Master Password or Recovery Key; bind the core-owned picked file/Safety Copy ID and bytes being inspected. Preview metadata may return; no credential does. Keep explicit replacement confirmation, preview expiry, discard and one-use pick behavior. |
| `change_password` (both `rotate` values) | `Settings.tsx: ChangePassword → NewPassword`; `App.tsx` Recovery Kit handoff | Native collects current and new Master Password plus confirmation, labels password change versus Key Rotation, then runs the existing atomic core operation. Rotation's new Recovery Kit remains native until confirmation; failed/cancelled rotation changes nothing on disk. |
| `set_settings` reauthentication | `Settings.tsx → PasswordModal` from #30; `settings.master_password` plus `session_generation` | Remove the password from WebView settings input; keep non-secret proposed values and generation. Core normalizes/defaults/platform-filters the candidate and requests native entry only when it weakens Auto-lock. Bind the exact candidate and current session; tightening remains prompt-free. |

Also update `src/api.ts`, `src-tauri/src/commands.rs`, `core.rs`, `lib.rs`, `build.rs`, `capabilities/main.json` and `src/strings.ts` as one migration. Remove raw-credential fallback routes and the obsolete React password/kit state in `Start.tsx`, `Settings.tsx`, `components.tsx`, `Note.tsx`, `Home.tsx` and `App.tsx`. `check_seed`, `check_private_key`, ordinary Note input and the terminal Emergency Reader are not Master Password IPC routes and keep their existing boundaries.

## Cancellation, concurrency and stale work

- Permit one native credential operation at a time; reject overlap instead of queuing hidden prompts. Native waiting must not hold `CoreState`'s mutex. Current `commands::blocking` holds it through KDF work: the implementation must split validated state capture, costly credential derivation and checked commit so lock/guard events can invalidate work promptly. Preserve core validation, throttling and save rollback while doing so.
- Bind each pending operation to the current Vault/header, phase, unlock generation, exact target/arguments and relevant document/source version. The polled status `revision` is not an authorization epoch. #30's `session_generation` helps reject re-unlock races but does not replace Note/input/source checks. Revalidate after native input, after derivation and immediately before reveal/copy/save/install/settings commit.
- Cancel on native Escape/close, explicit WebView cancellation/navigation, reload, owner Lock, timeout, sleep, screen lock, user switch, replacement/password/rotation transitions, target edits/removal or Sharing Guard arrival. Wipe credentials, drop transient Wallet Keys and discard late callbacks; cancellation is not a wrong-password attempt. A released held reveal must never show or copy when derivation completes later.
- Hide an existing reveal before native entry. Native focus stays within this app, but genuine app switches and OS lock events still apply; do not blanket-suppress them with `DIALOG_OPEN`. Never run another operation after a cancelled panel or transfer its approval to a changed target.
- Keep native labels/keyboard focus/accessibility under Rust control. Show the actual action and validated target, preserve Enter/Escape/Tab/Space and screen-reader labels, disable text assistance and credential copy/cut/drag, and clear native fields on all exits. Keep credential text out of window titles, logs, events, errors, clipboard and serialized status. New authentication diagnostics must omit Note titles too; existing owner-requested visible-field copying and copy-source feedback retain their current rules. The native panel must stay in the protected main window; a separate sheet/dialog needs an ADR-0002 revision and independent first-frame capture protection before use.

## Implementation sequence and acceptance

1. Prototype native controls, focus, accessibility and cancellation on both OSes with fake credentials, without introducing new credential-bearing commands. Verify the same-window approach under Capture Hiding and Sharing Guard before wiring sensitive actions. Windows physical execution is a release prerequisite, not satisfied by cross-compilation.
2. Add one native-operation boundary with fake adapters and race tests, then migrate every table row and remove all old credential input/output payloads together. Tests must cover direct legacy IPC attempts, overlapping prompts, lock/guard/reload/re-unlock/Note changes during input and derivation, held release, wrong-password backoff, weak/mismatched new passwords, malformed/stale Backup picks, and save/rotation failure rollback. Reuse the existing core/session/vault-format suites rather than duplicating crypto logic.
3. Run fake-data native-flow tests on real macOS and Windows, including setup and Recovery Kit, both unlock kinds, recovery reset, every Wallet action, both password-change modes, Backup/Safety Copy inspection from every permitted phase, and #30 tightening/weakening. Inspect only fake WebView state/IPC/events/logs for credential markers; confirm native keyboard and VoiceOver/Narrator behavior and no native first-frame capture leak. Record exact OS/app versions and sanitized outcomes; no real values or private paths.
4. Update ADR-0003 (and ADR-0004's current WebView-password caveat) only to match shipped behavior and recorded limits. Retain that Notes entered/revealed in JavaScript and a convincing forged WebView prompt remain risks; native custody cannot stop an owner typing into a malicious imitation or protect a compromised OS/Rust core.

All runtime work and acceptance remain open. No native prompt, platform permission, credential, Keychain, provisioning or account operation has run for this design.
