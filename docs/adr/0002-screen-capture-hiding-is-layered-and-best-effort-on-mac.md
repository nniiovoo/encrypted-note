# Hiding from screen capture is layered, and only best-effort on Mac

The owner's requirement is that the app never shows up in third-party screen sharing or recording. On Windows 10 2004+ and Windows 11 the OS can exclude a window from capture (`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`), and Teams, Zoom, OBS, Discord, Meet in Chrome, Snipping Tool and Recall then see nothing. Microsoft still says it is "not a security feature": code injected into the app's process can switch it off. On macOS no public API guarantees it. Apple's docs call `NSWindow.sharingType = .none` "a legacy constant that macOS no longer uses", Apple DTS said in July 2025 "there are no public APIs for preventing screen capture" Tests on macOS 26.x and the 27 beta (2026) show the flag *is* honored by the standard paths: ScreenCaptureKit window and display streams (which current Chrome/Meet uses), `screencapture`, and Cmd+Shift+3/4/5. The window is simply absent from the capture. Specific recorders still leak it, though, including Zoom's GPU/unfiltered share mode, possibly QuickTime, and tools that re-apply their capture filter. It could also change in any macOS update. This is true whatever framework we choose. So we meet the requirement in layers, not with the OS switch alone: (1) **Capture Hiding** is always on as an extra layer, (2) **Hidden Fields** stay hidden until the owner chooses Show, and (3) a **Sharing Guard** covers the whole window and blocks Show while a known sharing or recording app is running. The app calls this protection "best-effort" and never says "guaranteed", on either platform. (Tauri's own docs overstate `setContentProtected`; don't copy their wording.)

## Consequences

- Set Capture Hiding at window creation (`"contentProtected": true`), never later from JavaScript. Setting it late left a ~240 ms capturable gap in tests.
- Only our main window is protected. Native alerts, file pickers, context menus, `<select>` popups and tooltips are separate OS windows and would appear in a share. While Unlocked, use in-page HTML modals, menus and dropdowns only, and keep one window. Native file pickers (for Backups) are allowed because they never show Note content.
- Window titles are visible to capture tools even when pixels aren't, so the title is always just "encrypted-note" and never a Note name.
- The app checks its own protection (Mac: read its window's `kCGWindowSharingState`; Windows: `GetWindowDisplayAffinity`, because tao ignores the set call's return value) and shows whether it's active. A dev script checks that `screencapture -l <windowid>` fails.
- Every screenshot of the app is blank, including our own for debugging, so there's a debug-build-only override and no user-facing "turn off protection" switch.
- On Windows a hidden-then-shown window can appear in captures as a black box instead of being excluded (Tauri issue #14189, the same bug as Electron #29085). Setting the affinity again doesn't help: Windows still reports `WDA_EXCLUDEFROMCAPTURE` in that state. We use Electron's fix (#31340): the main window is kept `WS_EX_LAYERED` (fully opaque), and the bit is re-added whenever tao rewrites the window's styles. This is untested on Windows so far; it's on the checklist below.
- The Windows self-check can't see that black-box state, since the affinity still reads back as set; it also checks that the layered bit is present. Before Windows 10 2004 the value acts as `WDA_MONITOR` (a black box too) and may still read back as set. In both cases the content stays hidden, but the status overclaims "excluded".
- Whether Capture Hiding blanks the window during legitimate AirPlay/Sidecar mirroring is untested. It's on the checklist.
- macOS offers no API that detects sharing before the first frame leaks, so the Sharing Guard uses a running-apps check.
- Meet or another web meeting running inside a browser can't be detected without extra OS permissions, so the Sharing Guard won't notice it; the other layers still apply.
- Manual test checklist, re-run after macOS or meeting-app updates: QuickTime, Cmd+Shift+5, Zoom (normal and GPU share modes), Meet in Chrome, Discord, OBS, Teams, iPhone Mirroring, macOS 27 Visual Intelligence; on Windows also Snipping Tool, Recall, and a Teams or OBS capture after hiding and re-showing the window (minimize/restore too), which must show no black box.
- Nothing here defends against a phone camera, an HDMI capture card, or malware already running as the owner.
