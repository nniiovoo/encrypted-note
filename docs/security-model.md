# Security model

> **Status: v1, personal project, not independently audited.** Keep an offline paper or metal backup of any Seed Phrase or Private Key that holds real funds. This app is a convenient extra copy, not your only one.

## What it protects against, and what it can't

| Protects | Doesn't protect |
|---|---|
| A stolen laptop or USB stick (Argon2id + XChaCha20-Poly1305, strong password required) | Malware already running on your computer (keyloggers, memory readers), and AI tools or other software running in your account, which work as you ([AI tools](guide.md#ai-tools-on-this-computer)) |
| Someone at your unlocked computer (Auto-lock, re-entering the password for wallets, hold-to-show for Wallet values) | A phone camera pointed at your screen, or someone watching it while you choose to show what you typed |
| Accidentally showing Hidden Fields while screen sharing (layered, see below) | A hacked operating system, or being forced to unlock |
| Clipboard history and Universal/cloud clipboard (copies are marked private, which clipboard tools, including OS history, aren't obliged to honor, and cleared after 30 s, or 60 s if you choose; Wallet Kinds always 30 s). A password you paste from another app gets none of this protection: this app can't mark it or clear it | Old copies of your Vault: they still open with the old password. An older copy put in place while the app is closed still opens: the app warns after unlock, but not if `settings.json` was changed or deleted too |
| | Tools you have given macOS Accessibility permission: they may read text the window shows, such as a shown value, which Capture Hiding doesn't hide, and they can bring the window forward and press Show or Copy (not tested) |
| | A replaced app: the Mac app is signed ad hoc, with no developer identity, so anything running as you may be able to swap it for one that records your Master Password (not tested) |

**Screen-capture hiding is best-effort on Mac.** Apple offers no API that guarantees it. Windows' exclusion is much stronger but still not a security boundary. That's why the app layers it with hidden-by-default fields and the Sharing Guard, which covers the window when known screen-sharing or recording apps are detected. See [ADR-0002](adr/0002-screen-capture-hiding-is-layered-and-best-effort-on-mac.md).

## How it works

- **Tauri v2.** React/TypeScript screens run in an untrusted WebView. Rust/native code owns keys and decrypted Notes. Ordinary Show returns one authorized Hidden Field; stored Wallet readouts remain native ([ADR-0003](adr/0003-tauri-with-secrets-kept-in-rust.md)). New/edited Hidden Field inputs still pass through JavaScript, so a compromised renderer can observe them.
- **Native credential entry.** Actual Master Password and Recovery Key entry, password suggestion/strength/confirmation and Recovery Kit display stay in native controls. Rust binds the exact action and checks cancellation, source state and expiry before committing. No credential or reusable approval is returned through IPC. Native/OS copies and the stack remain best effort; a fake renderer prompt or compromised native process remains a risk. See [native custody](native-credential-design.md).
- **Showing typed credentials (owner decision, 30 October 2026).** Master Password and Recovery Key entry boxes stay secure, masked fields; only the Recovery Kit step's retype box shows what is typed, because the key is on screen right above it, and it refuses copy and cut. Two opt-in views exist on Mac only, each off by default: a **Show what I type** tickbox on Recovery Key entry, off each time and never remembered, which shows a separate read-only line; and a **Hold to show what I typed** button on the New and Confirm Master Password boxes, which shows a snapshot while held, for about 10 seconds at most: the one of those two boxes that has the focus and holds text, otherwise the last-edited one. Show what I type turns itself off after about a minute with no typing. Neither applies to unlocking with a Master Password, Wallet actions, the current password, or Touch ID, and both refuse while a known screen-sharing or recording app is detected, even after the Sharing Guard is dismissed. The tickbox would also show a password typed into the Recovery Key box by mistake. Both are best-effort: the text is on screen while shown, and Capture Hiding is no guarantee. A suggested password is a third case of plain text on screen, on Mac and Windows: Suggest a password draws it on a separate line so it can be written down, assistive tools can read that line, and it is not refused while a known sharing app is detected after a dismissal. Windows has neither of the two opt-in views, because it has never been run on a real PC. Recovery Key entry on both platforms also has a character count and a typo check, which show nothing secret. All of this is described from the code until tested by hand.
- **Encryption.** Argon2id is calibrated on your machine (≥ 64 MiB). A random Vault Key and a separate Wallet Key are wrapped by your Master Password and by your Recovery Key ([ADR-0004](adr/0004-wallet-kinds-under-a-separate-key.md), [ADR-0005](adr/0005-password-change-rewraps-key-rotation-is-separate.md)). The file format is documented byte by byte in [FORMAT.md](FORMAT.md).
- **Reveal limits.** Logins, API Keys and Text use a 30-second reveal. Seed Phrases and Private Keys need the Master Password to view or edit, with hold-to-show or a 20-second timed reveal. The limits the owner can stretch, and the ones that stay fixed, are in [ADR-0006](adr/0006-everyday-key-use-limits-the-owner-can-stretch.md).
- **Show in the Editor (owner decision, 30 October 2026).** While typing a Login password, or an API Key's key or secret, the owner can press Show to read it before saving. It is off by default and never offered for Wallet Kinds or a Passphrase. The box stays a password input; the value is drawn on a separate line that can't be selected. It hides on window blur and 30 seconds after the press, with no extension. It is best-effort, like any text on screen, and is described from the code until tested by hand. See [ADR-0006](adr/0006-everyday-key-use-limits-the-owner-can-stretch.md).
- **Quick Unlock on Mac.** The source implementation uses a biometric-gated Secure Enclave key to wrap only the Vault Key in an encrypted private local file. No account, server, Apple Developer profile or persistent Keychain item is part of this route. Native Master Password verification is required after app restart and every seven days; Touch ID does not extend that deadline, release a Wallet Key or erase password backoff. This file uses filesystem access controls rather than Keychain app access-group isolation: another process with the same user's file access may copy it and request its own protected operation outside the app's process policy. Deleting the current file does not erase backup copies. [Custody details and physical acceptance](quick-unlock-design.md).
- **Show and Copy need the window in front.** The Rust core refuses Show and every Copy of a Note's field (whole, one line, or as NAME=value) while the app's window isn't in front, so a program working the app from the background gets "Show and Copy work only while this window is in front." A program that brings the window forward first gets past this. Described from the code; not tested by hand.
- **Where things are stored.** See [Where your keys are stored](guide.md#where-your-keys-are-stored). The Finder or File Explorer window opened from Settings is outside Capture Hiding and shows file names, dates and a path containing the user name, never Note content.
- **Backups.** A Backup is just a copy of the Vault file you save wherever you like (e.g. an exFAT USB stick) and open on your other computer. A USB stick has no per-account protection, so keep it unplugged when you're not using it. There's no sync by design ([ADR-0001](adr/0001-local-only-vault-moved-by-hand.md)).
- **Missing and older Vaults.** `settings.json` keeps the Vault's id and a count of its changes. If the Vault file is gone, Welcome says so and offers a Backup first. If an older copy of the same Vault opens, the app warns after unlock and refuses nothing, because a restore can be wanted. Touch ID turns off when the file was replaced by one with other credentials. The settings file isn't signed, so these catch mistakes, not someone who changes both files ([FORMAT.md section 14](FORMAT.md#14-the-settings-file-not-part-of-the-vault)).
- **Emergency Reader.** `crates/reader` is a small command-line tool that reads a Vault or Backup even if the app stops working ([how to use it](guide.md#if-the-app-wont-open)). It doesn't have the app's wiping allocator. It prints Notes only to a terminal, and warns when it sees signs of an AI tool's terminal, which it can't stop. `scripts/build-reader.sh` builds a copy to keep from merged `main`, and prints its SHA-256.
- **Optional Agent Companion.** A separate helper (an XPC service with its own App Sandbox container) can let the agent tools in one separate Mac account use one fixed OpenAI text tool with a separately created Agent Key. It can't open the Vault's container, receives nothing from the Vault, and stops on Stop, lock, sleep, grant expiry and quit. Its one destination, POST https://api.openai.com/v1/responses, is in `companion/policy.json`, whose pinned SHA-256 the helper checks before every Start; the broker refuses to load a policy that names any other. Its Agent Key is kept in a plain-text file that other non-admin Mac accounts can't open, and in Node.js memory, not encrypted Vault storage ([ADR-0009](adr/0009-optional-agent-companion-helper.md), [guide](agent-companion.md)).
- **Optional: agents storing keys (Mac).** The app's one way in from other programs ([ADR-0012](adr/0012-agents-store-and-manage-keys.md), [guide](agent-keys.md)). It is a Unix domain socket, not a network port, in `/Users/Shared/encrypted-note-keys`, a folder the owner's setup script makes (mode 700, plus one ACL entry that lets the agent account reach the socket but not list the folder). It exists only while the Vault is Unlocked and the owner's grant runs: at most one hour, and it ends on Stop, lock, Auto-lock, sleep, screen lock, user switch and quit. The app takes the connecting program's account from the kernel and answers only the one Standard account named in Settings (never the owner's own, a system account, or one in the admin, wheel or operator group); everything else is closed with no reply. The agent's tool checks the same way that the socket is run by the owner's account. An agent can make five requests, about only the Notes marked "added by an agent" and not in Trash: store (the owner types the value into the app's ordinary editor), list, edit details, and ask to replace a value or delete. No request field can hold a value and every reply is a fixed shape, so names, visible details, ids and dates are all that reach the agent and its AI company. Where-a-key-is-used edits wait for the owner's Allow; every Wallet Kind edit and every delete also need the Master Password; values change only by the owner typing them. One request waits at a time, for at most 5 minutes. **Limits:** any program in the agent account can use it while the grant runs; a tricked agent can still add junk keys, raise requests the owner has to refuse, and rename or re-describe the keys it added; the route can't tell a real request from a planted one, so each confirm is the protection; and it does nothing about AI tools running in the owner's own account, which work as the owner anyway. It needs two entitlements, pinned like the others:
  - the one `temporary-exception.files.absolute-path.read-write` entry for that folder;
  - one `temporary-exception.sbpl` rule letting the app listen on, and accept, a Unix socket only there. The file entry alone doesn't cover sockets under the sandbox (found 2026-11-09).
- **Vocabulary.** [CONTEXT.md](../CONTEXT.md) defines Vault, Note, Kind, Hidden Field, Recovery Kit and the rest.

## Tested so far

- **Automated:** `./scripts/check.sh` runs the test suite, including tamper tests over every byte of a Vault file and the RFC 9106 and XChaCha20-Poly1305 reference vectors. It also searches the source for network code outside the Agent Companion's one request and its loopback server, and for Unix sockets outside the agent route (a text search, not a sandbox), scans tracked files for known key shapes and for Seed Phrases written out as English words, and fails if an entitlement file differs from its pinned hash. CI runs it on Mac and Windows.
- **Earlier UI, by hand on macOS 26:** the main flows, clipboard privacy markers, the Sharing Guard with real apps, and a Backup read back by the Emergency Reader. Those records do not validate the new native credential/readout controls or local Touch ID custody. Screen-capture evidence and remaining matrix: [capture-test.md](capture-test.md).
- **New native flows:** fake-data core/coordinator, custody/lifecycle and private-file checks exist. Actual Touch ID enrollment/unlock, biometric ACL behavior, restart/sleep/switch races, native accessibility and first-frame capture acceptance remain pending. So do Show what I type, Hold to show what I typed, Show in the Editor and pasting into password boxes: none has been tested by hand.
- **Windows:** native runtime behavior has **not yet been tested on a real Windows PC**. Compilation checks cannot establish it; the app sets no crash-dump limit there (it does on Mac), and whether a Windows crash dump could hold keys or Notes hasn't been checked. Windows Hello remains later.
- **Agents storing keys:** checked with fictional data only: core and route tests for every request, refusal and lifecycle end, the socket and the real agent tool end to end in one account, and the screens in the fixture. Nothing has run on a real Mac with a separate agent account, in the sandboxed app or from a real agent tool, and the fake-key drill and the security review that ADR-0012 asks for before real keys are still to do ([what's left](agent-keys.md#what-has-been-checked-and-what-hasnt)). It's unavailable on Windows.
- **Agent Companion:** checked with fictional data only, including that the packaged helper can't read a fake Vault canary in the app's container ([results](agent-key-validation.md#integrated-helper-2026-10-26)). No real key, live request or ChatGPT connection yet; it's unavailable on Windows.
